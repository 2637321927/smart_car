# 智能车道路遥测台

这个工具在Windows电脑上接收小车UDP数据，并在浏览器中显示：

- 鸟瞰坐标下的道路左线、中线和右线。
- `CTL1`控制波形、速度环、方向误差、陀螺仪和最近超时信息。
- 红块与目标板矩形、`item_flag`和识别状态。
- 远距离红块候选、连续确认次数、轮廓面积和目标板检测阶段。
- 最近10秒最多6条自选UDP参数曲线，内置速度环、角速度环和绕行预设。
- JSONL录像、时间轴回放、逐事件查看和0.25～4倍速播放。
- 示波器与录制、载入和时间轴位于同一工作台，回放时无需来回切换区域。
- 拖动或播放时间轴时，道路线、目标框、状态摘要和UDP参数同步切换到同一时刻。
- 回放时自选曲线同步使用录像对应时刻的UDP参数，不会继续显示实时数据。
- 桌面端第一行依次为道路图、示波器/录像和快速控制，支持按住 `Ctrl` 在道路图上滚轮调整道路图与示波器宽度。
- 第二行集中显示全部在线调参项；连续量使用滑块和数值框，离散模式使用开关或分段按钮。
- 第三行是横跨页面的录像回放时间轴；发车和停车使用醒目的大按钮。
- 调参快照会写入录像，拖动回放时间轴时控件同步显示当时参数且禁止误发指令。
- 向小车 `8082` 端口发送现有VOFA调参命令。

## 1. 网络设置

小车使用两条相互独立的UDP目标链路：

```cpp
const std::string VOFA_TARGET_IP = "192.168.43.146";
const std::string DEBUGGER_TARGET_IP = "192.168.43.155";
```

| 接收端 | 地址 | 内容 |
|---|---|---|
| VOFA | `192.168.43.146:8080` | `#vofa=1;` 时回传参数波形，默认关闭 |
| 道路调试器 | `192.168.43.155:8080` | `udp=1/2` 时接收`CTL1`控制包和250ms调参状态；`udp=2`时额外接收`RDL1`道路包 |
| 调试图像接收端 | `192.168.43.155:8081` | JPEG调试图像 |

运行本软件的电脑IPv4应为 `192.168.43.155`。启动软件后，控制台也会列出电脑当前可用的IPv4地址。

小车当前IP为 `192.168.43.93`，调参命令发送到：

```text
192.168.43.93:8082
```

第一次运行时，如果Windows防火墙询问Node.js网络权限，请允许专用网络访问，否则收不到小车UDP。

## 2. 启动

要求电脑安装Node.js 18或更新版本，不需要执行 `npm install`。

双击：

```text
tools\road_debugger\start_debugger.bat
```

或者在PowerShell中运行：

```powershell
cd tools\road_debugger
node server.js
```

然后打开：

```text
http://127.0.0.1:8765
```

## 3. 数据频率

先通过网页快捷按钮或VOFA命令选择发送内容：

| 命令 | 行为 |
|---|---|
| `#udp=0;` | 关闭参数和道路调试UDP，比赛时推荐 |
| `#udp=1;` | 向道路调试器发送12ms参数波形 |
| `#udp=2;` | 向道路调试器发送参数波形和道路左/中/右三线，默认模式 |
| `#vofa=0;` | 停止向 `192.168.43.146:8080` 回传波形，默认状态 |
| `#vofa=1;` | 临时向 `192.168.43.146:8080` 回传传统VOFA波形 |
| `#camStats=1/0;` | 开启或关闭250ms低频相机整帧性能统计，默认关闭 |

小车始终在自身 `8082` 端口非阻塞接收指令。关闭 `#vofa` 只停止小车向 `.146` 回传波形，不影响 `.146` 上的VOFA继续向小车发送调参、发车和停车指令。

| 数据 | 频率 | 说明 |
|---|---:|---|
| `CTL1`控制包 | 12ms | 固定212字节，包含轮速、PWM、视觉、角速度、绕行动态和最近超时 |
| 调参/状态JSON | 250ms | 滑块值、模式开关和UDP发送失败计数；相机统计开启时另发一个小型增量包 |
| `RDL1`道路包 | 最快20ms | 三线、瞄点、目标框和识别结果，最大824字节 |
| 趋势图 | 跟随`CTL1`或旧JSON | 浏览器只保留最近10秒 |

道路帧不会发送JPEG，只发送最多 `64×3` 个鸟瞰坐标点，完整UDP包约820字节，不会超过常见1500字节MTU。

## 4. 自选曲线与布局

示波器下拉框会自动列出当前UDP包里的全部数值参数。选择参数后点击“添加曲线”，最多可同时显示6条；点击示波器标题中的彩色标签可以删除对应曲线。

内置三组快捷预设：

| 预设 | 曲线 |
|---|---|
| 速度环 | 左右轮实际RPS、左右轮目标RPS |
| 角速度环 | 目标角速度、实际角速度 |
| 绕行 | 目标航向、累计航向、航向误差、差速输出 |

曲线选择会保存在浏览器 `localStorage.scopeChannels` 中，刷新页面后仍然保留。实时和回放共用同一组曲线，纵轴会根据当前可见数据自动缩放并包含零点。

桌面端第一行依次显示道路图、示波器和快捷指令，第二行显示全部在线调参控件，第三行横跨页面显示录像时间轴。红块和目标板缩略图位于道路图右下角。按住 `Ctrl` 并在道路图上滚动，可以在30%～70%之间调整道路图与示波器的相对宽度；点击道路图标题中的“图像 xx%”按钮恢复50%。比例保存在 `localStorage.roadColumnPercent` 中。

顶部按控制包、道路包和低频状态分别显示数据年龄。`CTL1`超过100ms显示警告、超过500ms显示离线；`RDL1`超过150ms只提示道路数据延迟，低频状态超过1000ms提示不同步。上述提示不会向小车发送停车命令。

连续参数拖动滑块时只在浏览器内预览，松开后才发送一次UDP指令，避免拖动过程高频轰炸小车。数值框在按回车或失焦后发送。录像回放时，第三行显示录像对应时刻的参数快照，所有调参控件自动锁定。

## 5. 录制与回放

点击“开始录制”后，服务器把参数事件和道路帧分别写入：

```text
tools/road_debugger/recordings/*.jsonl
```

停止录制后，在录像列表中点击“刷新”和“载入”，即可使用时间轴、单步和倍速播放。回放不会向小车发送任何命令。

## 6. 调参命令

输入框接受现有VOFA命令，例如：

```text
#P=300;
#I=10;
#spd=20;
#AIM=0.30;
#yGuardDps=500;
#run=1;
#run=0;
```

网页只是通过UDP转发命令，小车端仍使用 `main.cpp` 中原来的命令解析逻辑。

## 7. 自检

```powershell
cd tools\road_debugger
npm run check
```

该命令检查Node.js语法，并验证`CTL1`、`RDL1`、旧JSON、调参状态、录像和命令转发。
