# 高速滚动识别与双方案绕行设计及实验方案

> 当前阶段：高速绕行第一版已实现，本文同时作为原理说明、参数记录和上车实验清单。
>
> 目标：先完成低速、直道和缓弯分阶段验证，再根据实测数据修订参数与状态切换条件。

> **2026-07-25实现更新：** 当前代码已改为远距离红块两级检测。候选检测使用
> `ROI_TOP=60`、最小面积`55`、最小宽度`7`、宽高比`1.2~5.5`，并要求最近3次检测至少命中2次；第一票先以`0RPS`基准进行速度闭环预减速，第二票确认后再输出`-9000 PWM`主动制动，严格红块
> 确认后再进行三帧推理。候选成立到绕行结束期间暂停十字/环岛；目标位置处
> 赛道切线继续计算，但默认不作为绕行航向参考。
>
> **2026-07-25三阶段更新：** 运动状态改为`TURN_OUT → PASS_SHORT → TURN_TO_TRACK`。
> 默认速度依次为`0/10/10RPS`，向外转角为`42°`，第二转回到赛道参考航向
> `0°`，车头积分达到或越过对应目标角后即可切换阶段；回程中线有效时在同一个
> 8ms方向周期恢复35RPS普通巡线。最短斜行距离和
> 目标后安全余量均为`0m`。
>
> **2026-07-25边线实验方案：** 新增`dbMode=1`，左绕直接用原始左边线瞄准、
> 右绕直接用原始右边线瞄准，持续`dbSideMs`后切回中线。该时间默认`500ms`，
> 可在`500~2000ms`内调节。切回后若中线不足15点，
> 左绕按`+55dps`向右找线，右绕按`-55dps`向左找线；中线恢复后立即交还普通巡线。
> 原三阶段角度闭环保留为默认`dbMode=0`。
>
> 重要说明：文中的直道、缓弯绕行数据均为用于解释控制流程的虚构示例，不是实测结果。

## 1. 任务目标

改造前的历史流程为：

```text
检测到红色
→ 停车约 200ms
→ 停车状态下完成多帧推理
→ 按固定轮速、固定时间执行绕行
→ 恢复巡线
```

当前已实现流程为：

```text
35RPS 正常巡线
→ 只执行低负担红色检测
→ 检测到红色后才启动 NCNN
→ 远距候选成立后主动制动，释放后以 0RPS 基准识别
→ 三帧投票完成且制动完成后按dbMode进入所选绕行方案
→ dbMode=0：三阶段角度闭环，第二转完成后恢复巡线
→ dbMode=1：按dbSideMs定时瞄准边线，切回中线并在中线恢复后恢复巡线
```

`dbMode=0`的运动阶段默认基准速度依次为`0RPS`、`10RPS`、`10RPS`；
`dbMode=1`全程使用`dbForwardRps=10RPS`。实测换算关系采用`1RPS≈0.047m/s`。

## 2. 总体控制思路

| 数据或模块 | 作用 | 使用时间 |
|---|---|---|
| 红色检测 | 判断是否值得启动目标板分类 | K0 开启后低频运行 |
| NCNN 分类 | 判断直行、左绕或右绕 | 只在检测到红色且观察夹角合适后运行连续 3 帧 |
| 视觉赛道切线 | 给出直道或缓弯的实时方向基准 | 接近目标和绕行期间 |
| MPU6050 角速度 | 角速度内环反馈 | 正常行驶和绕行期间 |
| MPU6050 角度积分 | 记录本次绕行中的连续车身航向 | 从红色触发到回正结束 |
| 编码器积分 | 判断已经行驶多远、是否越过目标 | 从红色触发到回正结束 |
| 速度环 | 执行左右轮目标速度 | 始终运行 |

正常巡线期间不累计绕行航向和绕行距离。每次红色触发时清零积分，最后回正后立即停止并丢弃本次积分，避免把陀螺仪长期零偏带入整圈行驶。

## 3. 识别与性能策略

### 3.1 无红色时不运行 NCNN

```text
K0 关闭
→ 不检测红色
→ 不运行 NCNN

K0 开启、没有红色
→ 每 2 帧对裁剪后的识别区域做一次 HSV 红色检测
→ 不调用 NCNN

确认检测到红色
→ 提取目标 ROI
→ 主动制动释放后把基准速度设置为 0RPS，普通方向环继续叠加左右差速
→ 判断目标板观察角度
→ 观察角度合适时才提交 NCNN
```

红色检测只处理有效裁剪区域，不对整幅 `320×240` 图像执行完整 HSV、形态学和轮廓搜索。

识别等待和三帧推理期间继续执行道路处理与普通方向环。`0RPS`只是新的
基准速度，不会把左右轮强制设成相同值；方向环仍根据实时 `latest_error`
调整差速，避免减速过程中车身姿态突然改变。

### 3.2 未来异步推理策略

未来代码使用单 worker、单槽队列：

- worker 空闲时接收一张新的 ROI。
- worker 正在推理时跳过当前帧，不积压已经过期的图像。
- 获取 3 个不同有效帧后停止该目标的所有后续推理。
- `2:1` 或 `3:0` 时采用多数结果。
- `1:1:1`、超时或不足 3 个有效帧时按直行处理。
- worker 无任务时使用条件变量休眠，不轮询占用 CPU。

当前第一版采用同步连续三帧推理：触发帧在观察夹角合格时可直接作为第 1 帧，
识别期间保持`0RPS`基准和普通方向环，因此仍可能通过左右反向差速原地修正车头。若前两帧有效结果一致，会直接形成多数票并提前结束；否则最多处理三帧。异步 worker 仍属于后续性能升级，不是本版必需条件。

持续刹车测试使用`#test_brake=1;`开启、`#test_brake=0;`关闭。它复用相同的
远距候选、严格红块确认和投票流程；制动达到`dbBrakeRelease`后保持零PWM等待
识别结束，随后直接将`run`置0，绝不进入绕行。测试开关默认关闭，开启后会跨停车
保持，便于重复发车测试。主动制动专用PWM范围为`0~9000`，默认`9000`；普通
反向输出仍限制为`4000`。

## 4. 目标位置、切线与车板连线

目标板法向与目标所在位置的赛道切线平行，但在弯道上，小车到目标板的连线通常不平行于赛道切线。

```text
车辆到目标板的连线
≠ 目标位置处赛道切线
```

三个方向必须分开使用：

| 几何量 | 计算来源 | 用途 |
|---|---|---|
| 车辆到目标板连线 | 目标与车辆的相对位置 | 判断目标在哪一侧、计算观察夹角 |
| 目标位置处赛道切线 | 目标附近的鸟瞰中线 | 判断目标板法向和绕行方向 |
| 车辆当前航向 | 本次绕行的陀螺仪积分 | 判断车辆实际转过多少角度 |

### 4.1 目标地面位置

红块底边基本接触地面，因此计划使用红块底边中心作为目标地面像素：

```text
target_ground_pixel =
(red_center_x, red_bottom_y)
```

通过现有 `mapx/mapy` 逆透视表映射到鸟瞰坐标，再寻找距离该位置最近的赛道中线点，得到：

```text
target_track_index
target_along_track_distance
```

其中 `target_along_track_distance` 表示车辆沿赛道中线到达目标位置需要行驶的距离，不是相机到目标板的空间直线距离。

### 4.2 目标位置处切线

目标位置处切线仍用于观察夹角和调试显示，但默认不再直接作为绕行航向零度。
使用`#dbUseTangent=0;`时，脚本以运动开始时的车头方向为零度；只有明确发送
`#dbUseTangent=1;`后，才恢复“目标位置处赛道切线+阶段偏角”的原控制方式。
该开关在每次绕行运动开始时锁存，运动中途修改只影响下一次绕行。

在 `target_track_index` 前后约 `0.10m` 的中线点上进行小规模直线拟合，得到：

```text
target_track_heading
```

该运算只涉及最多约 10 个点的乘加和一次角度计算，且只在发现红色之后运行，预期开销远低于 HSV、轮廓搜索和 NCNN 推理。

### 4.3 观察夹角

目标板法向使用目标处赛道切线，目标板到车辆的方向使用车板连线：

```text
view_angle =
目标板法向 与 目标板到车辆连线 的夹角
```

未来计划只在 `view_angle <= 46°` 且 ROI 完整时提交推理，避免使用严重斜视的目标板图像。该阈值需要明日实验验证。

## 5. 有限时域陀螺仪与编码器积分

### 5.1 积分生命周期

正常巡线期间：

```text
drive_by_yaw_deg 不累计
drive_by_distance_m 不累计
```

目标会话开始时：

```text
drive_by_yaw_deg = 0°
drive_by_distance_m = 0m
phase_distance_m = 0m
记录当前有效赛道切线
记录触发时目标沿赛道距离
清空角速度内环积分
```

绕行期间每个控制周期：

```text
drive_by_yaw_deg += gyro_dps × dt

drive_by_distance_m +=
平均编码器RPS × db_rps_to_mps × dt
```

第二转完成后：

```text
立即恢复正常视觉巡线
立即恢复 35RPS 目标速度
停止并丢弃本次陀螺仪积分
停止并丢弃本次编码器积分
```

一次三阶段绕行预计持续约`1～2s`。陀螺仪积分在这一有限时域内是重要的连续姿态数据，但不会在正常巡线中无限累计。

### 5.2 陀螺仪与视觉赛道方向融合

陀螺仪积分提供本次绕行中的车辆航向：

```text
vehicle_yaw = drive_by_yaw_deg
```

视觉鸟瞰中线提供赛道相对车头的方向：

```text
track_relative_heading
```

开启切线参考时，换算为本次绕行局部坐标中的赛道方向：

```text
track_heading =
vehicle_yaw + track_relative_heading
```

默认关闭切线参考时：

```text
track_heading = 脚本启动时的vehicle_yaw
```

三阶段目标航向：

```text
desired_vehicle_yaw =
track_heading + 当前阶段横移偏角
```

航向误差：

```text
heading_error =
desired_vehicle_yaw - vehicle_yaw
```

这样可以同时满足：

- 陀螺仪积分提供 8ms 级连续姿态。
- 需要对比弯道效果时，可手动开启视觉切线参考。
- 视觉短暂丢失时，可以在短时间内继续依靠陀螺仪积分。
- 回正结束后丢弃积分，不产生长期漂移。

### 5.3 编码器比例必须实测

定距测速结果为 `10RPS≈0.47m/s`，因此正式使用：

```text
db_rps_to_mps = 0.047
```

该值来自当前定距测速，是三阶段距离积分的实测初值；更换轮胎、传动比或场地后仍应重新标定。

## 6. 双方案绕行状态机

`#dbMode=0;`选择原三阶段角度闭环，`#dbMode=1;`选择边线瞄准实验方案。
模式在每次绕行运动开始时锁存，绕行中途修改`dbMode`只影响下一次脚本。

### 6.1 三阶段角度闭环（dbMode=0）

| 阶段 | 相对所选参考航向的偏角 | 默认基准速度 | 目的 |
|---|---:|---:|---|
| `TURN_OUT` | 绕行侧 `42°` | `0RPS` | 原地向目标板侧方转出 |
| `PASS_SHORT` | 继续保持绕行侧 `42°` | `10RPS` | 沿斜向轨迹越过目标板 |
| `TURN_TO_TRACK` | 回到赛道参考航向 `0°` | `10RPS` | 反向转向并交还巡线 |
| `RECOVER_CENTER_LINE` | 左绕`+55dps`、右绕`-55dps` | `10RPS` | 仅在第二转结束仍找不到中线时启用 |
| 完成 | 普通视觉方向环接管 | `35RPS` | 中线可靠后立即恢复普通巡线 |

左右绕行完全镜像。以左绕为例：第一次目标为左偏`42°`，第二次回到参考航向`0°`，因此第二次实际反转约`42°`。

航向目标和角速度目标为：

```text
desired_yaw = locked_track_heading + phase_offset
target_yaw_rate = clamp(
    heading_kp * heading_error - heading_kd * gyro_dps,
    -dbHMax,
    +dbHMax)
```

目标角速度继续交给现有`gIP/gII/gRMax`内环产生左右轮差速。两个转向阶段的主切换条件为：

```text
沿本阶段转动方向投影后的车头积分
>= 沿同方向投影后的目标角
```

旧的“航向误差进入容差且角速度稳定，连续满足3个8ms周期”只保留为尚未越线时的兜底，
不再是正常切换必须满足的条件。

`PASS_SHORT`必须同时满足：

```text
phase_distance >= dbPassDist                 // 默认0.32m
distance_since_trigger >= target_distance + dbSafeDist  // 当前默认不追加余量
```

第一次转出时，车头积分沿转出方向达到或越过`dbTurnAngle`就进入斜行；不再要求
角速度先降到接近0。第二次转回沿回程方向达到或越过`dbReturnBias`后先检查中线：
中线可靠时，8ms方向定时器直接清除绕行控制器历史、设置35RPS基准并释放
`drive_by_busy`；中线仍丢失时进入`RECOVER_CENTER_LINE`，左绕给
`+dbRecoverDps`、右绕给`-dbRecoverDps`，保持`dbExitRps`直到中线恢复。
旧的“角度在容差内且角速度稳定”判定只作为未越线时的兜底。默认
`dbRecoverDps=55dps`；陀螺仪关闭或未就绪时回退为原来的`±100`视觉误差保护。
交还时不恢复识别前保存的旧差速。

#### 三阶段调参接口

| VOFA参数 | 作用 | 默认值 |
|---|---|---:|
| `dbUseTangent` | 是否使用目标位置处赛道切线作为绕行零度 | `0`（关闭） |
| `dbTurnAngle` | 第一次向绕行侧偏转的角度 | `42deg` |
| `dbReturnBias` | 第二转结束后朝赛道内侧的预偏角 | `30deg` |
| `dbPassDist` | `PASS_SHORT`阶段最短斜行距离 | `0.32m` |
| `dbSafeDist` | 越过目标位置后的安全余量 | `0m` |
| `dbTurnRps` | `TURN_OUT`基准速度 | `0RPS` |
| `dbForwardRps` | `PASS_SHORT`基准速度 | `10RPS` |
| `dbExitRps` | `TURN_TO_TRACK`基准速度 | `10RPS` |
| `dbHMax` | 航向外环允许输出的最大目标角速度 | `505dps` |
| `dbRecoverDps` | 回程丢线时固定目标角速度 | `55dps` |
| `dbNormalSpd` | 脚本成功交接后的巡线基准速度 | `35RPS` |

旧命令`#dbExitDist=...;`仍会被接收，但只打印“已废弃并忽略”，不参与三阶段状态切换。

### 6.2 两套方案共用的回程丢线保护

无论选择哪套方案，回到赛道时都必须先确认中线剩余有效点不少于15点。左绕后
找不到中线就向右给`+dbRecoverDps`，右绕后找不到中线就向左给`-dbRecoverDps`，
默认幅值为`55dps`，直到中线恢复。陀螺仪不可用时才回退到`±100`视觉误差。
`dbMode=0`找线时保持`dbExitRps`，`dbMode=1`保持`dbForwardRps`。

### 6.3 边线瞄准实验方案（dbMode=1）

该方案保留相同的红块检测、主动制动和识别投票，只替换识别完成后的运动控制：

| 状态 | 左绕 | 右绕 | 结束条件 |
|---|---|---|---|
| `FOLLOW_SIDE_LINE` | 原始左边线作为瞄准线 | 原始右边线作为瞄准线 | 持续`dbSideMs`，默认`500ms` |
| `RECOVER_CENTER_LINE` | 切回中线，丢线时给`+dbRecoverDps`向右找线 | 切回中线，丢线时给`-dbRecoverDps`向左找线 | 中线剩余有效点不少于15点 |
| 完成 | 普通中线和方向环接管 | 普通中线和方向环接管 | 同一个8ms方向周期恢复`dbNormalSpd` |

边线阶段如果指定边线自身不足3点，左绕暂时给`-100`继续向左，右绕暂时给
`+100`继续向右，防止边线瞬间消失时提前反转。强制误差直接进入现有方向环，
仍受方向环的误差限幅、角速度环和最大轮速差保护。

新方案不在脚本内部使用陀螺仪角度积分或距离切换，全程采用
`dbForwardRps`（默认`10RPS`）作为基准速度。若`#gyro=1`，普通方向环仍是
“视觉误差外环+角速度内环”；若`#gyro=0`，则使用原视觉PD。

边线瞄准持续时间可在线调节：

```text
#dbSideMs=500;    // 最短500ms，也是默认值
#dbSideMs=1200;   // 持续瞄准边线1.2s
#dbSideMs=2000;   // 最长2000ms
```

小车端会把小于`500ms`的输入限制为`500ms`，把大于`2000ms`的输入限制为
`2000ms`。增大该值会让车辆沿所选边线行驶更久，通常横向绕出距离也更大。
`FOLLOW_SIDE_LINE`的安全超时为“`dbSideMs+500ms`”；为保证高
`dbForwardRps`时也能完整执行设定时间，该阶段不再使用固定距离上限。后续
`RECOVER_CENTER_LINE`仍使用原来的`1.5s/0.80m`保护。

为避免无限找线，两个视觉状态都保留停车保护，但阈值不同：边线瞄准采用
`dbSideMs+500ms`超时，恢复中线采用`1.5s/0.80m`。实车测试建议先使用
前端`TEST绕行`分别验证左右符号和持续时间。

## 7. 直道完整绕行示例

> **虚构示例：** 以下数字只解释控制流程，不是实测结果。

假设左绕目标在触发时位于前方`0.50m`，安全余量为`0m`，开始运动脚本时车辆从红色触发点累计行驶了`0.30m`。

| 阶段 | 示例持续时间 | 基准速度 | 航向变化 | 距离说明 |
|---|---:|---:|---:|---|
| 识别与主动制动 | `约100ms` | 释放后`0RPS`基准 | 普通方向环持续工作 | 推理和制动都完成后进入脚本 |
| `TURN_OUT` | `180ms` | `0RPS` | `0°→左42°` | 原地完成第一次转向 |
| `PASS_SHORT` | `400ms` | `10RPS` | 保持左42° | 阶段至少行驶`0.32m`且越过目标距离 |
| 距离判定 | - | - | 保持左42° | 总里程达到目标距离`0.50m`后允许第二转 |
| `TURN_TO_TRACK` | `180ms` | `10RPS` | `左42°→参考0°` | 回到赛道参考方向 |
| 普通巡线 | 下一个8ms周期 | `35RPS` | 最新视觉误差接管 | 不再执行额外回正阶段 |

`PASS_SHORT`不是只看固定时间。速度变化或识别距离变化时，编码器双距离条件仍然会阻止车辆在尚未越过目标板时提前转回。

## 8. 缓弯完整绕行示例

> **虚构示例：** 以下角度只用于说明弯道几何关系。

以下示例明确开启`dbUseTangent=1`。假设识别时车辆当前航向为`+8°`，目标位置处赛道切线为`+16°`，并执行左绕：

| 阶段 | 锁定的赛道切线 | 相对偏角 | 车辆目标航向 |
|---|---:|---:|---:|
| `TURN_OUT` | `+16°` | 左偏`42°` | `+58°` |
| `PASS_SHORT` | `+16°` | 左偏`42°` | 保持`+58°` |
| `TURN_TO_TRACK` | `+16°` | 回到参考`0°` | `+16°` |
| 普通巡线 | 使用最新视觉中线 | 由视觉误差决定 | 跟随当前缓弯继续调整 |

第二次转向不是回到陀螺仪积分的`0°`，也不是长期追踪识别时的`+16°`。脚本只在短时间内把车头送到朝向赛道的一侧；释放控制后，普通视觉外环会根据当时真实赛道继续修正，随后丢弃本次有限时域角度积分。

## 9. 明日实验计划

### 9.1 实验一：编码器 RPS 到实际速度标定

准备一段长度准确的直道，建议使用 `3m`。在进入测量区前让车辆速度稳定。

分别测试：

```text
15RPS
25RPS
35RPS
```

每种速度重复 3 次。

| 目标 RPS | 次数 | 实测距离 | 用时 | 左轮平均 RPS | 右轮平均 RPS | 实际速度 m/s | 换算系数 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 15 | 1 | 3m |  |  |  |  |  |
| 15 | 2 | 3m |  |  |  |  |  |
| 15 | 3 | 3m |  |  |  |  |  |
| 25 | 1 | 3m |  |  |  |  |  |
| 25 | 2 | 3m |  |  |  |  |  |
| 25 | 3 | 3m |  |  |  |  |  |
| 35 | 1 | 3m |  |  |  |  |  |
| 35 | 2 | 3m |  |  |  |  |  |
| 35 | 3 | 3m |  |  |  |  |  |

计算：

```text
实际速度 = 实测距离 / 用时

平均编码器RPS =
(左轮平均RPS + 右轮平均RPS) / 2

换算系数 =
实际速度 / 平均编码器RPS
```

如果不同速度得到的换算系数差异超过 `10%`，暂不进入距离闭环实现，需要先检查编码器比例或测量方法。

## 11. 收到数据后的计划修订

收到实验结果后，按以下顺序修订：

1. 计算正式的 `db_rps_to_mps`。
2. 确定 `35→20RPS` 的实际减速时间和减速距离。
3. 判断当前红色检测距离是否满足高速提前量。
4. 判断 3 帧投票在不同观察角度下是否可靠。
5. 确定最大允许推理观察夹角。
6. 确定最短斜行距离和目标后安全余量。
7. 判断直道与缓弯是否能够共用同一最大偏角。
8. 评估陀螺仪在 1～2 秒内的积分误差。
9. 验证车辆横向偏移后视觉中线是否仍能提供切线。
10. 根据实测数据生成最终代码实施计划和分阶段验收标准。

当前`dbMode=0`三阶段代码保留为稳定基线，`dbMode=1`用于边线方案对比实验。
