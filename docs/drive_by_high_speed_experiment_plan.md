## 1. 任务目标

改造前的历史流程为：

```text
检测到红色
→ 停车约 200ms
→ 停车状态下完成 5 帧推理
→ 按固定轮速、固定时间执行绕行
→ 恢复巡线
```

当前已实现流程为：

```text
35RPS 正常巡线
→ 只执行低负担红色检测
→ 检测到红色后才启动 NCNN
→ 连续 3 帧推理，同时将基准速度直接改为 20RPS
→ 到达触发距离后开始 S 形绕行
→ 绕行期间使用陀螺仪角度积分和编码器距离积分
→ 视觉赛道切线用于修正缓弯参考方向
→ 回正后立即恢复正常巡线和 35RPS
```

本方案不在软件中额外设计速度斜坡。车辆从 `35RPS` 切换到 `20RPS` 后，由现有速度环完成减速。实测换算关系采用 `1RPS≈0.047m/s`。

## 2. 总体控制思路

| 数据或模块 | 作用 | 使用时间 |
|---|---|---|
| 红色检测 | 判断是否值得启动目标板分类 | K0 开启后低频运行 |
| NCNN 分类 | 判断直行、左绕或右绕 | 只在检测到红色且观察夹角合适后运行连续 3 帧 |
| 视觉赛道切线 | 给出直道或缓弯的实时方向基准 | 接近目标和绕行期间 |
| MPU6050 角速度 | 角速度内环反馈 | 正常行驶和绕行期间 |
| MPU6050 角度积分 | 记录本次绕行中的连续车身航向 | 从红色触发到回正结束 |
| 编码器积分 | 判断已经行驶多远、是否越过目标 | 从红色触发到回正结束 |
| 速度环 | 执行左右轮目标速度 | 始终运行 |

正常巡线期间不累计绕行航向和绕行距离。每次红色触发时清零积分，最后回正后立即停止并丢弃本次积分，避免把陀螺仪长期零偏带入整圈行驶。

## 3. 识别与性能策略

### 3.1 无红色时不运行 NCNN

```text
K0 关闭
→ 不检测红色
→ 不运行 NCNN

K0 开启、没有红色
→ 每 2 帧对裁剪后的识别区域做一次 HSV 红色检测
→ 不调用 NCNN

确认检测到红色
→ 提取目标 ROI
→ 基准速度直接设置为 20RPS，普通方向环继续叠加左右差速
→ 判断目标板观察角度
→ 观察角度合适时才提交 NCNN
```

红色检测只处理有效裁剪区域，不对整幅 `320×240` 图像执行完整 HSV、形态学和轮廓搜索。

识别等待和三帧推理期间继续执行道路处理与普通方向环。`20RPS` 只是新的
基准速度，不会把左右轮强制设成相同值；方向环仍根据实时 `latest_error`
调整差速，避免减速过程中车身姿态突然改变。

### 3.2 未来异步推理策略

未来代码使用单 worker、单槽队列：

- worker 空闲时接收一张新的 ROI。
- worker 正在推理时跳过当前帧，不积压已经过期的图像。
- 获取 3 个不同有效帧后停止该目标的所有后续推理。
- `2:1` 或 `3:0` 时采用多数结果。
- `1:1:1`、超时或不足 3 个有效帧时按直行处理。
- worker 无任务时使用条件变量休眠，不轮询占用 CPU。

当前第一版采用同步连续三帧推理：触发帧在观察夹角合格时可直接作为第 1 帧，
识别期间保持 `20RPS` 基准和普通方向环。异步 worker 仍属于后续性能升级，不是本版必需条件。

## 4. 目标位置、切线与车板连线

目标板法向与目标所在位置的赛道切线平行，但在弯道上，小车到目标板的连线通常不平行于赛道切线。

```text
车辆到目标板的连线
≠ 目标位置处赛道切线
```

三个方向必须分开使用：

| 几何量 | 计算来源 | 用途 |
|---|---|---|
| 车辆到目标板连线 | 目标与车辆的相对位置 | 判断目标在哪一侧、计算观察夹角 |
| 目标位置处赛道切线 | 目标附近的鸟瞰中线 | 判断目标板法向和绕行方向 |
| 车辆当前航向 | 本次绕行的陀螺仪积分 | 判断车辆实际转过多少角度 |

### 4.1 目标地面位置

红块底边基本接触地面，因此计划使用红块底边中心作为目标地面像素：

```text
target_ground_pixel =
(red_center_x, red_bottom_y)
```

通过现有 `mapx/mapy` 逆透视表映射到鸟瞰坐标，再寻找距离该位置最近的赛道中线点，得到：

```text
target_track_index
target_along_track_distance
```

其中 `target_along_track_distance` 表示车辆沿赛道中线到达目标位置需要行驶的距离，不是相机到目标板的空间直线距离。

### 4.2 目标位置处切线

在 `target_track_index` 前后约 `0.10m` 的中线点上进行小规模直线拟合，得到：

```text
target_track_heading
```

该运算只涉及最多约 10 个点的乘加和一次角度计算，且只在发现红色之后运行，预期开销远低于 HSV、轮廓搜索和 NCNN 推理。

### 4.3 观察夹角

目标板法向使用目标处赛道切线，目标板到车辆的方向使用车板连线：

```text
view_angle =
目标板法向 与 目标板到车辆连线 的夹角
```

未来计划只在 `view_angle <= 45°` 且 ROI 完整时提交推理，避免使用严重斜视的目标板图像。该阈值需要明日实验验证。

## 5. 有限时域陀螺仪与编码器积分

### 5.1 积分生命周期

正常巡线期间：

```text
drive_by_yaw_deg 不累计
drive_by_distance_m 不累计
```

进入 S 形接管瞬间：

```text
drive_by_yaw_deg = 0°
drive_by_distance_m = 0m
phase_distance_m = 0m
记录当前有效赛道切线
记录触发时目标沿赛道距离
清空角速度内环积分
```

绕行期间每个控制周期：

```text
drive_by_yaw_deg += gyro_dps × dt

drive_by_distance_m +=
平均编码器RPS × db_rps_to_mps × dt
```

回正完成后：

```text
立即恢复正常视觉巡线
立即恢复 35RPS 目标速度
停止并丢弃本次陀螺仪积分
停止并丢弃本次编码器积分
```

一次 S 形预计持续约 `1～2s`。陀螺仪积分在这一有限时域内是重要的连续姿态数据，但不会在正常巡线中无限累计。

### 5.2 陀螺仪与视觉赛道方向融合

陀螺仪积分提供本次绕行中的车辆航向：

```text
vehicle_yaw = drive_by_yaw_deg
```

视觉鸟瞰中线提供赛道相对车头的方向：

```text
track_relative_heading
```

换算为本次绕行局部坐标中的赛道方向：

```text
track_heading =
vehicle_yaw + track_relative_heading
```

S 形目标航向：

```text
desired_vehicle_yaw =
track_heading + 当前阶段横移偏角
```

航向误差：

```text
heading_error =
desired_vehicle_yaw - vehicle_yaw
```

这样可以同时满足：

- 陀螺仪积分提供 8ms 级连续姿态。
- 视觉切线修正缓弯方向。
- 视觉短暂丢失时，可以在短时间内继续依靠陀螺仪积分。
- 回正结束后丢弃积分，不产生长期漂移。

### 5.3 编码器比例必须实测

定距测速结果为 `10RPS≈0.47m/s`，因此正式使用：

```text
db_rps_to_mps = 0.047
```

该值不是正式参数。当前全局里程计按轮胎周长直接换算，与实车经验速度不一致，高速绕行不能直接照搬，必须先完成定距测速。

## 6. S 形绕行状态机

| 阶段 | 相对赛道航向目标 | 目的 |
|---|---:|---|
| `SHIFT_OUT_A` | 左右方向对应 `±25°` | 向要求的一侧移出 |
| `SHIFT_OUT_B` | `0°` | 重新与赛道平行 |
| `PASS_TARGET` | `0°` | 沿赛道方向通过目标 |
| `SHIFT_IN_A` | 与第一次相反的 `∓25°` | 向原赛道中心回移 |
| `SHIFT_IN_B` | `0°` | 最终回正 |
| 完成 | 正常视觉巡线 | 立即恢复，不增加额外直行阶段 |

航向外环计划采用：

```text
target_yaw_rate =
clamp(heading_kp × heading_error,
      -max_yaw_rate,
      +max_yaw_rate)
```

目标角速度继续交给现有 `gIP/gII/gRMax` 内环产生左右轮差速。

航向阶段初步完成条件：

```text
abs(heading_error) <= 2°
abs(gyro_dps) <= 20dps
连续满足 3 个 8ms 控制周期
```

开始回线的距离条件：

```text
绕行总距离
>= 触发时目标沿线距离 + 目标后安全余量
```

安全余量暂定为 `0.30m`，等待实测后调整。

## 7. 直道完整绕行示例

> **虚构示例：** 以下数字仅用于解释状态机，不可直接作为实车参数。

假设：

```text
巡线速度：35RPS，约 1.645m/s
识别速度：20RPS，约 0.94m/s
首次红色检测距离：1.30m
S 形触发距离：0.80m
目标后安全余量：0.30m
最大相对航向偏角：25°
三帧识别总耗时：约 70ms
```

### 7.1 识别与接近

| 相对时刻 | 状态 | 目标速度 | 目标距离 | 说明 |
|---:|---|---:|---:|---|
| `0ms` | 正常巡线 | 35RPS | 1.30m | 首次稳定检测到红色 |
| `0ms` | 开始目标会话 | 20RPS基准 | 1.30m | 方向环继续在20RPS上叠加差速 |
| `23ms` | 第 1 帧完成 | 20RPS基准 | 约 1.28m | 分类为左绕 |
| `46ms` | 第 2 帧完成 | 20RPS基准 | 约 1.26m | 分类为左绕 |
| `70ms` | 第 3 帧完成 | 20RPS基准 | 约 1.23m | 分类为直行，最终 2:1 左绕 |
| `150ms` | 减速基本完成 | 20RPS基准 | 约 1.16m | 实际速度接近 0.94m/s |
| `330ms` | 绕行持续进行 | 脚本速度 | 按实测距离 | 角度环和编码器积分接管 |

### 7.2 S 形阶段

| 阶段 | 示例持续时间 | 航向积分变化 | 总距离积分变化 |
|---|---:|---:|---:|
| `SHIFT_OUT_A` | 220ms | `0°→+25°` | `0→0.31m` |
| `SHIFT_OUT_B` | 220ms | `+25°→0°` | `0.31→0.62m` |
| `PASS_TARGET` | 340ms | 保持约 `0°` | `0.62→1.10m` |
| `SHIFT_IN_A` | 220ms | `0°→-25°` | `1.10→1.41m` |
| `SHIFT_IN_B` | 220ms | `-25°→0°` | `1.41→1.72m` |

因为：

```text
触发距离 0.80m + 安全余量 0.30m = 1.10m
```

所以车辆累计行驶约 `1.10m` 后才开始回线，保证目标已经位于车后。最后回正后，下一个方向控制周期立即恢复正常视觉巡线，不执行额外固定直行。

## 8. 缓弯完整绕行示例

> **虚构示例：** 以下角度用于说明弯道几何关系，不是实测参数。

假设目标位于右缓弯：

```text
首次检测时车辆附近赛道切线：+6°
目标位置处赛道切线：+16°
车辆到目标板连线方向：+31°
目标板法向方向：+16°
```

观察夹角：

```text
view_angle = abs(31° - 16°) = 15°
```

`+31°` 只表示目标板相对车辆的位置，`+16°` 才是目标位置处赛道方向，不能让车头朝 `+31°` 行驶。

### 8.1 缓弯 S 形过程

| 阶段 | 当前赛道切线 | 横移偏角 | 车辆目标航向 |
|---|---:|---:|---:|
| 开始接管 | `+8°` | `0°` | `+8°` |
| `SHIFT_OUT_A` | `+8°→+12°` | `+25°` | `+33°→+37°` |
| `SHIFT_OUT_B` | `+12°→+15°` | `0°` | `+15°` |
| `PASS_TARGET` | `+15°→+20°` | `0°` | `+15°→+20°` |
| `SHIFT_IN_A` | `+20°→+22°` | `-25°` | `-5°→-3°` |
| `SHIFT_IN_B` | `+22°→+24°` | `0°` | `+24°` |

最终陀螺仪积分可能为：

```text
drive_by_yaw_deg ≈ +24°
```

这不代表没有回正，因为赛道本身已经转过约 `24°`。真正的回正条件是：

```text
车辆航向 - 当前赛道切线 ≈ 0°
```

当车辆航向约为 `+24°`、赛道切线也约为 `+24°` 时，相对误差为零，可以立即恢复正常巡线。随后丢弃本次 `+24°` 的短期积分。

### 9.1 实验一：编码器 RPS 到实际速度标定

准备一段长度准确的直道，建议使用 `3m`。在进入测量区前让车辆速度稳定。

分别测试：

```text
15RPS
25RPS
35RPS
```

每种速度重复 3 次。

| 目标 RPS | 次数 | 实测距离 | 用时 | 左轮平均 RPS | 右轮平均 RPS | 实际速度 m/s | 换算系数 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 15 | 1 | 3m |  |  |  |  |  |
| 15 | 2 | 3m |  |  |  |  |  |
| 15 | 3 | 3m |  |  |  |  |  |
| 25 | 1 | 3m |  |  |  |  |  |
| 25 | 2 | 3m |  |  |  |  |  |
| 25 | 3 | 3m |  |  |  |  |  |
| 35 | 1 | 3m |  |  |  |  |  |
| 35 | 2 | 3m |  |  |  |  |  |
| 35 | 3 | 3m |  |  |  |  |  |

计算：

```text
实际速度 = 实测距离 / 用时

平均编码器RPS =
(左轮平均RPS + 右轮平均RPS) / 2

换算系数 =
实际速度 / 平均编码器RPS
```

如果不同速度得到的换算系数差异超过 `10%`，暂不进入距离闭环实现，需要先检查编码器比例或测量方法。

### 9.6 实验六：直道与缓弯赛道切线可用性

只在静态或低速测试时开启图传：

```text
#is_udp_img=1;
```

测试场景：

| 赛道 | 车辆姿态 |
|---|---|
| 直道 | 居中、左偏约 0.15m、右偏约 0.15m |
| 直道 | 车头相对赛道左偏约 10°、右偏约 10° |
| 缓弯 | 居中、内侧偏移、外侧偏移 |
| 缓弯 | 车头相对切线左偏约 10°、右偏约 10° |

每种状态保存鸟瞰图，检查：

- 白色中线是否连续。
- 横向偏离后是否仍有至少 10 个有效中线点。
- 缓弯中线方向是否平滑。
- 一侧边线丢失时，生成的中线是否仍可信。

测试完成后关闭图传：

```text
#is_udp_img=0;
```

## 11. 收到数据后的计划修订

收到实验结果后，按以下顺序修订：

1. 计算正式的 `db_rps_to_mps`。
2. 确定 `35→20RPS` 的实际减速时间和减速距离。
3. 判断当前红色检测距离是否满足高速提前量。
4. 判断 3 帧投票在不同观察角度下是否可靠。
5. 确定最大允许推理观察夹角。
6. 确定 S 形触发距离和目标后安全余量。
7. 判断直道与缓弯是否能够共用同一最大偏角。
8. 评估陀螺仪在 1～2 秒内的积分误差。
9. 验证车辆横向偏移后视觉中线是否仍能提供切线。
10. 根据实测数据生成最终代码实施计划和分阶段验收标准。

在以上数据确认之前，不执行高速绕行控制代码修改。
