# 小车实时性优化执行方案 V2

> 来源：根据 `docs/realtime_optimization_execution_plan.md` 末尾修改意见重新整理。  
> 关键修正：按键发车/调速度必须保留；速度环周期不改；编码器速度读取改为 `2ms` 两点滑动平均。

## 1. 最终意见吸收

| 主题 | 最终意见 | V2 执行结论 |
|---|---|---|
| 按键功能 | 按键发车/调速度必须保留 | 保留 K0/K1/K2 按键扫描，不再默认关闭整个前端 |
| TFT 屏幕 | 主要在终端看状态，屏幕可减少负载 | 只允许关闭 TFT 显示刷新，不关闭按键 |
| 速度环 | 速度环不做修改 | `speed_timer` 仍保持 `3ms`，`test_enc_and_motor_rps()` 不改 |
| 速度读取 | 改为 `2ms` 两点滑动平均 | `encoder_ave_timer` 改 `2ms`，滑动平均窗口从 3 点改 2 点 |
| UDP 波形 | 调车必须保留 | `udp_send_string()` 和 `udp_timer=10ms` 保持 |
| GYRO 日志 | 可以降频 | `[GYRO]` debug 打印从约 `400ms` 改为约 `800ms` |
| `std::endl` | 要改 | 活跃路径里的 `std::endl` 改为普通换行 |
| 其他 | 暂无意见 | 保留上一版低风险项，不做大重构 |

核心原则：

| 原则 | 说明 |
|---|---|
| 不影响实车操作 | K2 发车/停车、K1 调速度、K0 目标板开关继续可用 |
| 不动速度环控制周期 | 避免速度 PID 因周期改变而需要重调 |
| 只减轻速度读取压力 | 通过编码器读取 `2ms` + 两点平均降低 1ms timer 压力 |
| 屏幕和按键解耦 | 可以关闭 TFT 显示，但不能关闭按键扫描 |
| 保留调车观测 | UDP 波形和 VOFA 调参保留 |

## 2. 第一批执行范围

| 编号 | 改动 | 是否执行 | 说明 |
|---|---|---:|---|
| E1 | 编码器速度读取 `1ms -> 2ms` | 是 | 降低高频采样压力 |
| E2 | 编码器滑动平均 `3点 -> 2点` | 是 | 抵消周期变长带来的反馈延迟 |
| E3 | 速度环周期保持 `3ms` | 是 | 明确不修改速度环 |
| E4 | 保留 K0/K1/K2 按键 | 是 | 发车/停车、调速度、目标板开关继续可用 |
| E5 | TFT 显示默认关闭或可开关 | 是 | 只关闭屏幕绘制/刷新，不关闭按键 |
| E6 | `std::endl` 改普通换行 | 是 | 避免强制 flush |
| E7 | `[GYRO]` 调试打印降频 | 是 | 减少角速度环日志负载 |
| E8 | gyro timeout/stale 阈值临时放宽 | 是 | 减少高负载误判 |
| E9 | UDP 波形保留 | 是 | 调车必须 |

明确不做：

| 编号 | 暂不做内容 | 原因 |
|---|---|---|
| N1 | 不改速度环周期到 `4ms` | 你明确要求速度环不做修改 |
| N2 | 不关闭按键扫描 | 你明确要求按键发车/调速度保留 |
| N3 | 不关闭 UDP 波形 | 调车必须 |
| N4 | 不做主循环耗时统计 | 先不处理这个部分 |
| N5 | 不做线程优先级调整 | 第二轮再考虑 |
| N6 | 不做驱动缓存/进程隔离 | 当前 MPU6050 单独读取很快 |
| N7 | 不做 TFT 合并 flush 深改 | 先通过关闭屏幕显示降低负载 |

## 3. 具体实现方案

### 3.1 编码器速度读取：2ms 两点滑动平均

当前状态：

| 项目 | 当前值 |
|---|---:|
| 定时器 | `encoder_ave_timer` |
| 周期 | `1ms` |
| 平均窗口 | 3 点 |
| 等效平均时间 | 约 `3ms` |

V2 执行方案：

| 改动 | 方案 |
|---|---|
| 定时器周期 | `encoder_ave_timer.set_seconds_ms(1, ...)` 改为 `2` |
| 缓冲数组 | `buf1[3] / buf2[3]` 改为 `buf1[2] / buf2[2]` |
| 索引取模 | `idx = (idx + 1) % 3` 改为 `% 2` |
| 平均计算 | `sum / 3.0f` 改为 `sum / 2.0f` |
| 函数名 | 可暂不改名，注释改清楚“当前 2ms 调用” |

为什么这样改：

| 点 | 说明 |
|---|---|
| 采样频率降低 | 1ms timer 压力减半 |
| 平均点数降低 | 避免 2ms 周期下 3 点平均变成 6ms 延迟 |
| 等效平均时间 | 约 `4ms`，比原 `3ms` 稍慢但仍可接受 |
| 控制风险 | 比“2ms + 3点平均”更不容易拖慢速度反馈 |

验收：

| 指标 | 目标 |
|---|---|
| 编码器波形 | 不出现明显抖动放大 |
| 速度反馈延迟 | 不明显变大 |
| `Timeout summary` | 相比 1ms 采样减少 |
| 直道表现 | 不能因为速度读取变慢而更摇 |

回退策略：

| 问题 | 回退 |
|---|---|
| 速度波形太抖 | 保持 2ms，窗口临时回 3 点测试 |
| 速度反馈太慢 | 采样周期回 `1ms` |
| 直道明显变差 | 优先回退编码器读取改动 |

### 3.2 速度环保持不变

V2 明确不修改速度环：

| 项目 | 保持 |
|---|---|
| `speed_timer` 周期 | `3ms` |
| 回调函数 | `test_enc_and_motor_rps()` |
| 速度 PID 参数 | 不自动调整 |
| PWM 输出逻辑 | 不改 |

原因：

| 原因 | 说明 |
|---|---|
| 速度环直接影响车身响应 | 改周期可能导致 PID 等效参数变化 |
| 你明确要求不做修改 | 第一批只改速度读取 |
| 风险更低 | 避免改完后还要重新调速度 PID |

### 3.3 按键必须保留，只关闭 TFT 显示

上一版 `front_UI_switch` 写成“默认关闭前端所有线程”不符合最终意见。  
V2 改成：按键和屏幕分离。

推荐变量：

| 变量 | 默认值 | 含义 |
|---|---:|---|
| `volatile int tft_UI_switch` | `0` | 只控制 TFT 显示初始化、绘制、刷新 |

保留行为：

| 功能 | 是否保留 | 说明 |
|---|---:|---|
| K0 目标板开关 | 是 | 原功能保留 |
| K1 速度档位切换 | 是 | 调速度必须保留 |
| K2 发车/停车 | 是 | 发车/停车必须保留 |
| `front_ui_poll()` | 是 | 继续扫描按键 |
| `front_ui_is_running()` | 是 | 速度环/方向环继续依赖 |
| `front_ui_hold_stop()` | 是 | 停车安全逻辑继续保留 |

关闭行为：

| 功能 | 默认关闭 | 说明 |
|---|---:|---|
| `lq_tft18_drv_init()` | 是 | `tft_UI_switch==0` 时不打开 TFT |
| `draw_ui()` | 是 | `tft_UI_switch==0` 时不画屏 |
| TFT flush | 是 | `tft_UI_switch==0` 时不刷屏 |

实现要求：

| 位置 | 要求 |
|---|---|
| `front_ui_init()` | 无论屏幕开关如何，都要保证按键可用、停车状态初始化 |
| `front_ui_poll()` | 不因 `tft_UI_switch==0` 直接返回；仍然扫描 K0/K1/K2 |
| `draw_ui()` | 只有 `tft_UI_switch==1` 且 TFT ready 时才调用 |
| `stop_car()` | 不依赖 TFT，必须始终能清零 |
| `start_car()` | 不依赖 TFT，必须始终能发车 |

注意：

```text
本轮不再新增“关闭整个 front_ui 的开关”。
如果要加开关，只能加“关闭 TFT 屏幕显示”的开关。
```

### 3.4 是否还需要 VOFA 发车/停车命令

因为 K2 按键必须保留，VOFA 发车/停车不再是必须项。

V2 建议：

| 命令 | 是否第一批做 | 理由 |
|---|---:|---|
| `#run=1;` / `#run=0;` | 可选，不强制 | K2 已保留，VOFA run 只是备用 |
| `#target=1;` / `#target=0;` | 可选，不强制 | K0 已保留 |
| `#tft=1;` / `#tft=0;` | 可选 | 如果希望运行中开关屏幕，可后续做 |

第一批推荐：

```text
不强制新增 #run。
先保留原按键发车/停车方式，避免引入新的状态入口。
```

如果后续觉得终端发车更方便，再单独增加 `#run`，但不作为本轮必须项。

### 3.5 UDP 波形保留

保持：

| 项目 | V2 策略 |
|---|---|
| `udp_timer` | 保持 `10ms` |
| `udp_send_string()` | 保持 |
| VOFA/UDP 波形字段 | 保持 |
| UDP 图传 | 继续默认 `is_udp_img=0` |

不做：

| 不做项 | 原因 |
|---|---|
| 不关闭 UDP 波形 | 调车必须 |
| 不限流 UDP 波形 | 第一批不动观测链路 |
| 不新增图传限帧 | 图传默认关闭，暂不处理 |

### 3.6 `std::endl` 改普通换行

执行方案：

| 位置 | 处理 |
|---|---|
| 环岛日志 | 保留内容，`std::endl -> '\n'` |
| 前端按键日志 | 保留内容，`std::endl -> '\n'` |
| 主循环退出日志 | 若仍使用 `std::endl`，改普通换行 |

不做：

| 不做项 | 原因 |
|---|---|
| 不删除环岛日志 | 你认为环岛不常进，可以保留 |
| 不关闭按键日志 | 按键触发低频 |

### 3.7 `[GYRO]` 日志降频

执行方案：

| 项目 | 当前 | V2 建议 |
|---|---:|---:|
| `gyro_yaw_rate_control_print_debug(50)` | 约 `400ms` 一次 | 改为 `100`，约 `800ms` 一次 |

保留内容：

| 字段 | 保留原因 |
|---|---|
| `age` | 判断 gyro 数据新鲜度 |
| `read last/min/avg/max` | 判断读取耗时 |
| `timeout` | 判断是否持续超时 |
| `I_freeze` | 判断积分是否冻结 |

### 3.8 gyro 阈值临时放宽

执行方案：

| 参数 | 当前 | V2 建议 |
|---|---:|---:|
| `kGyroReadTimeoutMs` | `50ms` | `100ms` |
| `kGyroStaleFreezeMs` | `30ms` | `60ms` |

说明：

| 点 | 说明 |
|---|---|
| 这是诊断/保护阈值 | 不是控制目标 |
| 后续可收紧 | 实车稳定后再逐步压回更严格值 |
| 不改变 gyro reader 周期 | reader 仍保持 `5ms` |

## 5. 执行顺序

| 顺序 | 操作 | 验证 |
|---|---|---|
| 1 | `std::endl` 改普通换行 | 编译通过，日志仍可见 |
| 2 | `[GYRO]` 降频，gyro 阈值放宽 | `#gyro=1` 后日志更低频 |
| 3 | 编码器读取改 `2ms` 两点平均 | UDP 波形中速度反馈正常 |
| 4 | TFT 显示开关默认关闭 | 启动不刷 TFT |
| 5 | 确认 K0/K1/K2 按键仍可用 | K2 能发车停车，K1 能调速度 |
| 6 | 实车测试 | 对比 timeout、gyro age、直道表现 |

## 7. 回退策略

| 问题 | 优先回退 |
|---|---|
| 按键不能用 | 立即回退 front_ui 相关修改 |
| 发车/停车异常 | 立即回退 front_ui 相关修改 |
| 速度波形抖动明显 | 两点平均改回三点，或采样回 1ms |
| 速度响应变慢 | 采样回 1ms |
| gyro 日志不够看 | debug 间隔 `100 -> 50` |
| gyro 长期使用旧数据 | stale 阈值 `60 -> 30` 复查 |

## 8. 最终验收标准

| 指标 | 标准 |
|---|---|
| 按键 | K0/K1/K2 全部保留可用 |
| 速度环 | `speed_timer=3ms`，控制函数不改 |
