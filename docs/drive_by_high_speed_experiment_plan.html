1. 任务目标

当前目标板流程为：

检测到红色
→ 停车约 200ms
→ 停车状态下完成 5 帧推理
→ 按固定轮速、固定时间执行绕行
→ 恢复巡线

计划改造为：

35RPS 正常巡线
→ 只执行低负担红色检测
→ 检测到红色后才启动 NCNN
→ 3 帧异步推理，同时将目标速度直接改为 24.5RPS
→ 到达触发距离后开始 S 形绕行
→ 绕行期间使用陀螺仪角度积分和编码器距离积分
→ 视觉赛道切线用于修正缓弯参考方向
→ 回正后立即恢复正常巡线和 35RPS
本方案不在软件中增加速度斜坡。目标速度从 35RPS 直接切换到 24.5RPS，由现有速度环和车辆约 150ms 的响应完成减速。

2. 总体控制思路

数据或模块作用使用时间
红色检测判断是否值得启动目标板分类K0 开启后低频运行

编码器积分判断已经行驶多远、是否越过目标只从 S 形开始到回正结束

正常巡线期间不累计绕行航向和距离。每次开始 S 形时清零积分，最后回正后停止并丢弃本次积分，避免陀螺仪零偏长期累计。

3. 识别与性能策略

3.1 无红色时不运行 NCNN

K0 关闭
→ 不检测红色，不运行 NCNN

K0 开启、没有红色
→ 每 2 帧对裁剪后的识别区域做一次 HSV 红色检测
→ NCNN worker 保持休眠

确认检测到红色
→ 提取目标 ROI
→ 目标速度直接设置为 24.5RPS
→ 判断目标板观察角度
→ 观察角度合适时才提交 NCNN

红色检测只处理有效裁剪区域，不对整幅 320×240 图像执行完整 HSV、形态学和轮廓搜索。

3.2 未来异步推理策略

  • worker 空闲时接收一张新的 ROI。
  • worker 正在推理时跳过当前帧，不积压过期图像。
  • 获取 3 个不同有效帧后停止该目标的所有后续推理。
  • 2:1 或 3:0 采用多数结果。
  • 1:1:1、超时或不足 3 帧时按直行处理。
  • worker 无任务时通过条件变量休眠。
当前代码仍然是停车后同步推理 5 帧。明日实验测量的是当前识别能力和性能基线，不代表高速版已经实现。

4. 目标位置、切线与车板连线

目标板法向与目标所在位置的赛道切线平行，但在弯道上，小车到目标板的连线通常不平行于赛道切线。

车辆到目标板的连线 ≠ 目标位置处赛道切线
几何量计算来源用途
车辆到目标板连线目标与车辆的相对位置判断目标在哪一侧、计算观察夹角
目标位置处赛道切线目标附近的鸟瞰中线判断目标板法向和绕行方向
车辆当前航向本次绕行的陀螺仪积分判断车辆实际转过多少角度

4.1 目标地面位置

红块底边基本接触地面，计划使用红块底边中心：

target_ground_pixel =
(red_center_x, red_bottom_y)

通过现有 mapx/mapy 逆透视表映射到鸟瞰坐标，再寻找最近的赛道中线点，得到 target_track_index 和 target_along_track_distance。后者是沿赛道中线的距离，不是相机到目标板的空间直线距离。

4.2 目标位置处切线

在目标中线索引前后约 0.10m 的点上做小规模直线拟合，得到 target_track_heading。运算只涉及约 10 个点的乘加和一次角度计算，且只在发现红色后运行，开销远小于图像处理和推理。

4.3 观察夹角

view_angle =
目标板法向 与 目标板到车辆连线 的夹角

未来计划只在 view_angle <= 45° 且 ROI 完整时提交推理。该阈值需由明日实验验证。

5. 有限时域陀螺仪与编码器积分

5.1 积分生命周期

正常巡线：
drive_by_yaw_deg 不累计
drive_by_distance_m 不累计

进入 S 形：
drive_by_yaw_deg = 0°
drive_by_distance_m = 0m
phase_distance_m = 0m
记录赛道切线和目标沿线距离
清空角速度内环积分

绕行每个控制周期：
drive_by_yaw_deg += gyro_dps × dt
drive_by_distance_m += 平均编码器RPS × db_rps_to_mps × dt

回正完成：
恢复正常视觉巡线和 35RPS
停止并丢弃本次两项积分

一次 S 形预计持续约 1～2s。陀螺仪积分在有限时域内是重要的连续姿态数据，但不会在正常巡线中无限累计。

5.2 陀螺仪与视觉赛道方向融合

vehicle_yaw = drive_by_yaw_deg
track_heading = vehicle_yaw + track_relative_heading
desired_vehicle_yaw = track_heading + 当前阶段横移偏角
heading_error = desired_vehicle_yaw - vehicle_yaw
  • 陀螺仪积分提供 8ms 级连续姿态。
  • 视觉切线更新缓弯方向。
  • 视觉短暂丢失时可暂时依靠陀螺仪积分。
  • 回正后丢弃积分，不产生长期漂移。

5.3 编码器比例必须实测

db_rps_to_mps = 2 / 35 ≈ 0.0571
该数值只是根据“35RPS 约 2m/s”得到的经验初值。当前全局里程计按轮胎周长换算，与实车经验速度不一致，高速绕行必须先做定距测速。

6. S 形绕行状态机

阶段相对赛道航向目标目的
SHIFT_OUT_A左右对应 ±25°向要求的一侧移出
SHIFT_OUT_B0°重新与赛道平行
PASS_TARGET0°沿赛道方向通过目标
SHIFT_IN_A与第一次相反的 ∓25°向原赛道中心回移
SHIFT_IN_B0°最终回正
完成正常视觉巡线立即恢复，无额外直行阶段
 
target_yaw_rate =
clamp(heading_kp × heading_error,
      -max_yaw_rate,
      +max_yaw_rate)

目标角速度继续交给现有 gIP/gII/gRMax 内环产生左右轮差速。

阶段完成：
abs(heading_error) <= 2°
abs(gyro_dps) <= 20dps
连续满足 3 个 8ms 控制周期

开始回线：
绕行总距离 >= 触发时目标沿线距离 + 目标后安全余量

安全余量暂定 0.30m，等待实测后调整。

8. 缓弯完整绕行示例

虚构示例：以下角度只用于说明弯道几何关系。
首次检测时车辆附近赛道切线：+6°
目标位置处赛道切线：+16°
车辆到目标板连线方向：+31°
目标板法向方向：+16°

view_angle = abs(31° - 16°) = 15°

+31° 只表示目标相对车辆的位置，+16° 才是目标位置处赛道方向，不能让车头朝 +31° 行驶。

真正的回正条件：
车辆航向 - 当前赛道切线 ≈ 0°

赛道本身已经转过约 24°，所以积分不回到 0° 是正确现象。车辆航向和赛道切线都约为 +24° 时即可恢复正常巡线，随后丢弃本次短期积分。

实际速度 = 实测距离 / 用时
平均编码器RPS = (左轮平均RPS + 右轮平均RPS) / 2

11. 收到数据后的计划修订

  1. 计算正式的 db_rps_to_mps。
  2. 确定 35→24.5RPS 的实际减速时间和距离。
  3. 判断当前红色检测距离是否满足高速提前量。
  4. 判断 3 帧投票在不同观察角度下是否可靠。
  5. 确定最大允许推理观察夹角。
  6. 确定 S 形触发距离和目标后安全余量。
  7. 判断直道与缓弯是否能共用同一最大偏角。
  8. 评估陀螺仪在 1～2 秒内的积分误差。
  9. 验证横向偏移后视觉中线是否仍能提供切线。
  10. 根据实测数据生成最终代码实施计划和分阶段验收标准。
执行边界：在以上数据确认之前，不执行高速绕行控制代码修改。
